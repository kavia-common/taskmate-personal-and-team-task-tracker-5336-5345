# TaskMate Flutter App

TaskMate is a smart personal and team task tracker built with Flutter and Firebase.

## Prerequisites
- Flutter SDK (>= 3.29)
- Dart (>= 3.7)
- An existing Firebase project with the following products enabled:
  - Authentication (Google Sign-In)
  - Cloud Firestore (in Native mode)
  - Cloud Messaging (FCM)
  - Analytics (optional but recommended)
- FlutterFire CLI: `dart pub global activate flutterfire_cli`
- Firebase CLI: `npm i -g firebase-tools` then `firebase login`

## Environment Setup
1) Copy `.env.example` to `.env` and fill in values as needed.
2) Install dependencies:
   ```
   flutter pub get
   ```

## Preview Mode (No Firebase required)
Preview mode lets you run the app instantly without configuring Firebase. It uses in-memory mock repositories and a mocked signed-in user, and seeds sample Projects/Tags/Tasks.

Ways to run:
- Dedicated entrypoint (recommended):
  ```
  flutter run -t lib/main_preview.dart
  ```
- Or via main.dart using an env flag:
  1) Add to `.env`:
     ```
     PREVIEW_MODE=true
     ```
  2) Run normally:
     ```
     flutter run
     ```

Seeded data source:
- lib/dev/preview_seed.dart

Mocks:
- lib/dev/mock_repositories.dart

This mode never touches Firebase; no sign-in or backend setup is needed.

## Firestore Emulator (optional)
If you want to test Firebase-backed flow without production, you can point the app to a Firestore emulator.

Add the following to `.env`:
```
USE_FIRESTORE_EMULATOR=true
FIRESTORE_EMULATOR_HOST=localhost
FIRESTORE_EMULATOR_PORT=8080
```

Run:
```
flutter run
```

Notes:
- Emulator flags are only used when PREVIEW_MODE is not enabled.
- On Android emulators, use `10.0.2.2` for host if your emulator cannot reach `localhost`.

## Normal Run (with Firebase)
Ensure `lib/core/firebase_options.dart` is generated by FlutterFire and platform config files are present.

Run:
```
flutter run
```

## Firebase Configuration (Android & iOS)
This project uses FlutterFire configuration generated code and native config files.

### 1) Generate FlutterFire options
Run the FlutterFire CLI and direct output to our scaffolded path:
```
flutterfire configure \
  --project <your-firebase-project-id> \
  --platforms=android,ios \
  --out=lib/core/firebase_options.dart
```
- The generated `lib/core/firebase_options.dart` will replace the placeholder currently in `lib/core/firebase_options.dart`.
- `main.dart` imports from `core/firebase_options.dart` already.

Notes:
- The FlutterFire generated options file contains non-secret configuration and is safe to commit.

### 2) Add platform configuration files
- Android:
  - Download `google-services.json` for your Android app package.
  - Place it at: `android/app/google-services.json`
- iOS:
  - Download `GoogleService-Info.plist` for the iOS app.
  - Place it at: `ios/Runner/GoogleService-Info.plist`

Ensure the Android applicationId in `android/app/build.gradle.kts` matches your Firebase app configuration.

### 3) Apply Gradle plugins (Android)
If needed (depending on your setup):
- Top-level `android/build.gradle`:
  ```
  buildscript {
    dependencies {
      classpath 'com.google.gms:google-services:<latest>'
    }
  }
  ```
- App-level `android/app/build.gradle`:
  ```
  apply plugin: 'com.google.gms.google-services'
  ```

### 4) Enable Google Sign-In
- Firebase Console > Authentication > Sign-in methods: Enable Google provider.
- Android: Add SHA-1/256 to Firebase Console, then re-download `google-services.json`.
- iOS: Ensure `GoogleService-Info.plist` is in the Runner target; URL types include REVERSED_CLIENT_ID.

### 5) Cloud Messaging (FCM) overview
- Android: Requires `google-services.json` and notification permission (Android 13+).
- iOS: Configure APNs in Firebase Console and enable Push capability; request user permissions at runtime.

### 6) Analytics
Included via `firebase_analytics`. Ensure it’s enabled in your Firebase project. Implement consent as needed.

## Environment Variables Mapping
Keys are defined in:
- `lib/core/constants/env_keys.dart`

Available keys:
- FIREBASE_PROJECT_ID
- FIREBASE_ANDROID_APP_ID
- FIREBASE_IOS_APP_ID
- FIREBASE_API_KEY
- FIREBASE_MESSAGING_SENDER_ID
- FIREBASE_STORAGE_BUCKET
- GOOGLE_CLIENT_ID
- USE_FIRESTORE_EMULATOR (true/false)
- FIRESTORE_EMULATOR_HOST
- FIRESTORE_EMULATOR_PORT
- PREVIEW_MODE (true/false)

Notes:
- By default, we initialize Firebase using `DefaultFirebaseOptions.currentPlatform` from `lib/core/firebase_options.dart`.
- Do not put secrets in `.env`. Firebase client keys are not secrets, but follow your org policies.

## Running the App
- Preview mode:
  ```
  flutter run -t lib/main_preview.dart
  ```
  or:
  ```
  PREVIEW_MODE=true in .env
  flutter run
  ```
- Normal (Firebase-backed):
  ```
  flutter run
  ```

If missing config errors occur:
- Ensure `lib/core/firebase_options.dart` is generated.
- Ensure `android/app/google-services.json` and `ios/Runner/GoogleService-Info.plist` exist.
- Then:
  ```
  flutter clean
  flutter pub get
  flutter run
  ```

## Notifications
Local notifications (task reminders) via `flutter_local_notifications` and push notifications via `firebase_messaging` are scaffolded.

Local notifications:
- Channel: taskmate_reminders_channel (Android)
- Timezone-aware scheduling (`timezone` package)
- Code: `lib/features/notifications/notifications_service.dart`

Push notifications (stub):
- Code: `lib/features/notifications/push_notifications_stub.dart`
- To enable real push, complete APNs (iOS), ensure platform config files, and send tokens from backend.

## Code Pointers

- Auth UI: `lib/features/auth/presentation`
- Main tabs UI: `lib/features/main/main_tabs.dart`
- Repositories (Firestore): `lib/features/*/data/*_repository.dart`
- Domain models: `lib/features/*/domain`
- Preview seed: `lib/dev/preview_seed.dart`

## Troubleshooting
- Android: Notification permission needed on Android 13+. Verify via Settings.
- Firestore emulator: On Android emulator, use `10.0.2.2` host.
- If Firebase init fails in debug logs: confirm `firebase_options.dart` is present and platform files exist.
